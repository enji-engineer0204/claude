## 0. この資料の狙い

- **対象**：AIをまだ触っていない／チャットで質問する程度のメンバー・業務委託
- **ゴール**：AIを「一部の詳しい人の魔法」ではなく「**全員が面倒ごとを片付ける普通の道具**」にする
- **やり方**：抽象論でなく、**社内で実際に動いているAI**を実例に見せる（丸投げでなく"型"がある、と伝える）
- **トーン方針**：`躊躇っている前提にしない`。「みんな使っている前提で、そこにプラスアルファ」で話す
  （※これは社内アンケート「質問一覧」で既に決めていた方針。そのまま踏襲）

**なぜ今、うちで（ドラフト）**：トライリンクスは業務特化AIエージェント開発・推進(SUISHIN)・AIキャラ／音声AI・
ハンズオン研修を手がける会社で、強みは**数日単位の開発スピード**。一方で世の中では
**AIエージェントの約72%がPoC（お試し）止まり**で本番に乗らない。差がつくのは「導入」でなく**定着**——
全員が日常業務で当たり前に使えているか。だから社内浸透そのものが競争力になる。

> ⚠️メモ：ここは経営の言葉で微調整してください（数字・実感・事業ごとの狙いを1〜2行足すと刺さる）。

## 1. 結論：伸びる人のAIの使い方は「7つの型」

長島の実際の使い方を分解すると、以下7つが繰り返し出てきます。
**これがそのまま「社内に真似してほしい型」**です。ポイントは全部「AIが賢いか」ではなく
**「頼み方・使い切り方・組み込み方」**の話 ＝ 才能でなく"型"なので教育できる、という点。

| # | 型 | ひとことで | ダメな例（ありがち） |
|---|-----|----------|--------------------|
| 1 | **チャットで終わらせず「動くもの」を作り切る** | 質問でなく、業務が回るツール/パイプラインまで作る | 「やり方教えて」で満足、自分は動かない |
| 2 | **繰り返し作業を"コマンド/仕組み"に変える** | 一度作れば全員が一言で呼べる形にする | 毎回ゼロからプロンプトを書き直す |
| 3 | **手動MVP→半自動→全自動の順で出す** | まず手で回して価値検証、それから自動化 | いきなり全自動を作って複雑・頓挫 |
| 4 | **セキュリティ・権限・法務を"最初"に設計** | 秘密情報・公開範囲・規約・上限を先に決める | 動かしてから漏洩/規約/暴走で事故 |
| 5 | **丸投げせず「ガードレールと検証」を敷く** | 検証・dry-run・人の最終レビューを挟む | AIの出力をそのまま提出して信用を失う |
| 6 | **引き継げる「文脈ドキュメント」を残す** | CLAUDE.md / ハンドオフ文書で属人化を防ぐ | 作った本人しか分からない・1週間後に忘れる |
| 7 | **結果を"普段見る場所"に流し、道具は使い分ける** | Slack/Discord/Notionへ通知、モデルも用途で選ぶ | 出力がターミナルに埋もれ誰も見ない |

## 2. 型の中身 ＋ トライリンクス実例

### 型1：チャットで終わらせず「動くもの」を作り切る
「AIに聞く」で止めず、**業務が回る成果物**まで持っていく。
- **ai-news-tuber**：ニュース→AIキャラ解説ショート動画を**自動生成**する7段パイプライン（`npm run pipeline` 一発）
- **商談→改善点AI**：商談で聞いた声を貯め、**ボタン1つで「今週のプロダクト改善点」**が出る仕組み
- **補助金サクッとAI**：補助金申請書をAIで生成するプロダクトそのもの

> 💡伝え方：「AIは"賢い相談相手"じゃなく"作ってくれる部下"。最後まで作らせよう」

### 型2：繰り返し作業を"コマンド/仕組み"に変える
一度作れば、**組織の誰もが一言で同じ品質を呼び出せる**。
- **Notionタスク生成スキル（自作）**：「誰にアサイン／どのDBに書くか」を選べるよう改修し、タスク起票を自動化
- **/議事録・/日報 コマンド**：文字起こしを渡すと固定プロンプトが走り、決まった場所に自動格納
  → **「人によって出力がバラバラ・保存先が散らばる」問題を潰す**（AI駆動PMの考え方を実装）
- **Excel転記自動化**：手作業の転記をツール化

> 💡伝え方：「上手いプロンプトは"個人技"にせず、コマンドにして全員に配る」

### 型3：手動MVP→半自動→全自動の順で出す
**商談→改善点AI**の設計に、この型がそのまま出ています：
1. **手動MVP**：まずDBだけ作り、商談後に手で1レコード入力→週次でAIに「改善点出して」。*仕組み化の前に価値検証*
2. **半自動**：文字起こし取得を半自動化
3. **全自動**：週次で自動ダイジェスト生成

> 💡伝え方：「最初から全自動を狙わない。手で回して"効く"と分かってから自動化」

### 型4：セキュリティ・権限・法務を"最初"に設計
動かす前に、危ないところを先に囲う。
- **秘密情報**：APIキーは`.env`だけ・`.gitignore`必須・コード直書き禁止（ai-news-tuber開発ルール）
- **公開範囲**：見せる相手が違う情報は**DBごと分離**。稼働量は見せるが中身は伏せる**シークレットタスク方式**（コードネーム`TL-`採番＋限定共有）
- **法務・規約**：`LEGAL.md`／AI生成表記を常時表示／投稿リスクを low・medium・high で判定し**highは投稿禁止・mediumはSlack承認必須**
- **暴走・課金の防止**：`自動投稿は最初から有効化しない`／`初回は必ずunlisted`／予算アラート（警告5千・上限5万円）

> 💡伝え方：「AIに任せる＝事故る、ではない。**危険を先に言語化して囲えば安全に速く進める**」
> ⚠️メモ：ここは社内ルール化の起点。全社共通の「秘密情報の扱い」「AI表記」「承認ライン」を1枚に。

### 型5：丸投げせず「ガードレールと検証」を敷く
AIの出力を鵜呑みにせず、**機械チェック＋人の最終レビュー**を通す。
- リスク判定→台本生成→**スキーマ・禁止語句・出典・タイミングを検証**（ai-news-tuber）
- `--dry-run`（送らず試す）／カスタムエラー型で原因を分類／外部API呼び出しは指数バックオフで最大3回リトライ
- Claude Codeへの依頼ルール：`実装前に変更予定ファイルを説明させる`／`いきなり全部作らず単体テストしてから接続`
- 思想：**「AIが出すのはたたき台。最後は人が責任を持って仕上げる」**（AI駆動PMの学びとも一致）

> 💡伝え方：「AIは9割やってくれる。残り1割の"確認の一手"を仕組みに入れるのが人間の仕事」

### 型6：引き継げる「文脈ドキュメント」を残す
自分の頭の中を、AIにも人にも渡せる形に。
- **`CLAUDE.md` / `docs/PROJECT_CONTEXT.md` / ハンドオフ文書**：Claude Codeに渡す前提で"実装文脈だけ"を整理
- **実行ログ**：いつ何を決めた／方針転換したかを追記（後から経緯が分かる）
- Notion側も、タスクに詳細ページ＋実行ログをぶら下げて属人化を防ぐ

> 💡伝え方：「"作る"と同じくらい"次の人（未来の自分／AI）に渡せる状態"を大事にする」

### 型7：結果を"普段見る場所"に流し、道具は使い分ける
- **通知**：Slack（Block Kit）/ Discord / Notion DBへ自動格納。**普段見る場所に届ける**（ターミナルに埋もれさせない）
- **手段の再選択**：「Claude in Chromeで吸い出す想定 → 調べ直したら**公式MCP/APIの方が堅い**と判明し方針転換」。手段は状況で更新
- **モデルの使い分け**：リスク判定=Opus（安定・慎重）／生成=Sonnet（速い）。**コスト試算（約12円/本）**まで見て選ぶ

> 💡伝え方：「AIの出力は"今使ってるツール"に流し込む。道具・モデルは目的で選び直していい」

## 3. 明日から真似できる「頼み方テンプレ」

「何をどう頼めばいいか分からない」を潰すコピペ集。

### テンプレA：面倒ごとを自動化したい（汎用の型）
```
毎回◯◯を手作業でやっていて面倒。自動化したい。
【入力】どこから何を取るか（例：このSlackチャンネル / tl;dv / Notionの議事録DB）
【出力】どこに何を出すか（例：Notionの△△DBに1件ずつ / Slackの#□□に通知）
【制約】この情報は秘密 / 外部送信しない / 実行は1日1回でいい
まず"手で1回動く最小版"を作って。効くと分かったら、半自動→全自動に段階で進めたい。
```

**トライリンクス実タスク版（そのまま使える差し替え例）**

`▼ 議事録 → Notion格納`
```
tl;dv（オンライン）またはNotion AIノート（対面）の文字起こしを渡すので、決まった
フォーマット（Todo・決定事項・議事）で議事録を作り、議事録DBに1レコード追加して。
プロジェクト・会社名は既存の選択肢から推測して選ぶ（新規は作らない）。元リンクも保存。
```
`▼ 商談インサイトの蓄積 → 週次で改善点`
```
今日の商談で聞いた「課題・要望・刺さらなかった点」を、商談インサイトDBに1商談=1レコードで
タグ付き保存して。まずは手入力の最小版でいい。週末に「今週のプロダクト改善点」を頻度×インパクトで出して。
```
`▼ 補助金申請書のドラフト`
```
この会社の決算・事業概要をもとに、小規模事業者持続化補助金の申請書ドラフトを様式に沿って作って。
数値や固有事情が曖昧な箇所は【要確認】タグを付けて。最後は人がレビューする前提で。
```
`▼ 日報の自動生成`
```
このプロジェクトのSlackチャンネルと議事録DBから、前日の出来事を経緯込みで要約して、
プロジェクト日報DBに1件追加して。誰が読んでも状況が分かる粒度で。
```

### テンプレB：繰り返し作業をコマンド化して全員に配る
```
◯◯（例：議事録・日報・要件レビュー）を、毎回同じ品質・同じ保存先で作れるように
「コマンド化」して。固定プロンプト＋出力フォーマット＋保存先DBまで決めて、
他の人が一言（例：/議事録）で呼べる形にして。
```
> 実例：`/議事録`・`/日報`・`/要件定義レビュー`。上手いプロンプトは"個人技"にせずコマンドにして全員へ。

### テンプレC：安全に始める（ガードレール付き）
```
このツールを作る前に、先に決めたい：
①秘密情報はどれで、どう分離するか（.env / 公開範囲）
②AIの出力を出す前に何を検証するか（dry-run / スキーマ / 人の承認ライン）
③暴走・課金の上限
そのうえで、変更予定ファイルと設計をまず説明して。実装はその後。
```

## 4. 社内浸透ロードマップ（案）

### 4-0. まず"やり方"：説明より「一緒にやる」（体感ドリブン）
長島が実際に社外WSで使っている型。そのまま社内に効く（西武WS 当日ガイドより）。
- **説明は5分以内**。あとは画面共有で見せる＆一緒にやる（**4見せる：6手を動かす**）
- 相手に**「どう指示します？」と振る**。見てるだけにさせない
- 各デモで**「今まで何分？→今◯分」**と時間を本人に言ってもらう（＝ROIを本人の口から）
- ゴールは**実業務を1つAIで片付けて腹落ち→「社内で広げたい」**まで

### 4-1. 段階（フェーズ）

| フェーズ | 目標 | 具体アクション |
|---------|------|--------------|
| **①点火** | 「うちのAIで何ができるか」を体感 | §2の実例（ai-news-tuber / 商談改善AI / /議事録）をデモ。各自の"面倒ごと"を1つ書き出す |
| **②各自1個** | 全員が自分の面倒ごとを1つ自動化 | テンプレA配布＋相談窓口（Slack/Discordチャンネル）。小さな成功体験を作る |
| **③型化・共有** | 良い"頼み方"を横展開 | 上手いプロンプトを**コマンド化**して共有（型2）。プロンプト集・5分動画・部署別活用事例 |
| **④資産化** | 属人化とリスクを防ぐ | 型4の全社ルール（秘密情報・AI表記・承認ライン）＋型6の文脈ドキュメント文化を標準化 |

> 💡浸透の勘所：**①点火で終わらせず②"全員が自分の1個を持つ"まで**落とすのが分かれ目。
> 相談窓口と成功体験の共有が効く。アンケート「質問一覧」の設問がそのまま①②のネタ出しに使えます。

## 5. 想定される社内の不安とQ&A（素案）

※「質問一覧」で挙がっていた"ためらう理由"に沿って用意。

| よくある不安 | 返し方 |
|-------------|--------|
| 「うまく指示できるか不安」 | 型2の通り、良い指示は**コマンドに固めて配る**。普段の言葉で呼ぶだけでいい状態を作る |
| 「学ぶ時間がない」 | まず1個だけ（テンプレA）。手動MVPは"手作業＋AIに一言"から始められる |
| 「自分の業務で使えるシーンが浮かばない」 | §4①の"面倒ごと書き出し"から。議事録・日報・転記など全員に必ずある |
| 「精度・セキュリティが不安」 | 型4・型5。**秘密を先に分離し、出す前に検証・人がレビュー**する運用にすれば安全に前進できる |
| 「AIの回答がイマイチだった」 | 諦めず**頼み方を変えて再挑戦**（＝アンケートのB選択肢を標準行動に）。出力は"たたき台"前提 |
